- 범위: 배정 시작을 "배송 저장"에서 "주문 확정"으로 옮긴다. 후보가 없는 채로 확정 뒤 60초가 지나면 MASTER에게 수동 지정을 요청한다. 배정이 끝나면 order가 담당자에게 DM을 보낸다. delivery·order 코드, 새 내부 API, 계약 문서, ADR 0016 갱신, 확정 단계 추가 비용 측정

- 관련: 결정 로그 27 → 29, [ADR 0016](../../../docs/decisions/0016-delivery-manager-slack-dm.md), [T06](T06.md)(I-15), [T08](T08.md)

## 왜 (요약, 상세는 결정 로그 29)
1. order는 I-09 응답을 받은 뒤에 주문을 커밋한다. 배정은 배송 커밋 직후 수 ms 안에 끝나므로 배정 완료 알림이 주문 커밋보다 먼저 올 수 있다.
2. 주문 저장이 실패할 배송에도 담당자가 먼저 배정되어 보상 전까지 담당 건수에 섞인다.
3. 순서를 "주문 확정 → 배정 → 알림"으로 고정하면 두 문제가 함께 사라지고, 중복 방지 표시가 필요 없다.

## 흐름
```
order    I-09 호출 ─▶ 응답 ─▶ 주문 커밋 ─▶ ① 주문 확정 요청
delivery  배송 저장(미확정, 배정 안 함)     ─▶ 확정 커밋 ─▶ 배정
                                                 ├─ 성공 ─────────────▶ ③ 배정 완료 알림
                                                 └─ 후보 없음 ─▶ 대기, 주기 작업이 다시 시도
                                                                 └─ 확정 뒤 60초 초과 ─▶ ② 수동 지정 필요 알림
                                                                     MASTER가 D-04로 지정 ─▶ ③ 배정 완료 알림
order    ② MASTER에게 Slack(수동 지정 요청)    ③ 주문 ORDERED면 담당자에게 DM
```
- Slack은 order만 보낸다(ADR 0016). 주문 커밋 직후 DM 리스너는 지운다. 채널 Webhook 주문 알림은 그대로다.
- ③이 도착할 때 주문은 반드시 커밋돼 있다. 배송이 취소됐으면 배정·알림을 하지 않는다.
- ①은 한 방향 요청이다. order는 확정 커밋 응답(수 ms)만 받고 배정을 기다리지 않는다.
- 60초는 후보 0명일 때만 적용한다. user 장애는 수동 지정으로 넘기지 않고 계속 자동 재시도한다. 수동 지정 필요로 넘긴 배송은 자동 배정이 건너뛴다.

## 장애별 처리
| 상황 | 처리 |
|---|---|
| ① 확정 요청 실패(delivery 장애·타임아웃) | 주문은 되돌리지 않는다. 멱등이라 order가 몇 번 다시 보낸다. 그래도 실패하면 로그 |
| 확정을 끝내 못 받은 배송 | delivery 주기 작업이 오래된 미확정 배송을 order에 물어 확정 또는 정리 |
| ① 응답만 유실 | 다시 보내도 결과가 같다(멱등) |
| user 장애로 배정 불가 | 대기 유지, 자동 재시도. 2번에 세지 않는다 |
| ②·③ 요청 실패(order 장애) | 재전송하지 않는다(ADR 0016 7번). MASTER는 "수동 지정 필요" 배송을 목록으로 찾는다(프런트 협업) |

## 정한 것 (사용자가 기본값 승인, 2026-10-20, 상세는 결정 로그 29)
- 내부 API: ① I-19 주문 확정(order → delivery), ②·③ I-20 배정 결과 알림 `ASSIGNED|MANUAL_REQUIRED`(delivery → order), 안전망 I-21 주문 생성 결과(delivery → order)
- 확정 신호 유실 안전망: 1분마다 만든 지 2~30분 된 미확정 배송을 I-21로 묻고, 커밋된 주문이면 확정한다. 30분 넘은 고아는 더 묻지 않는다
- ① 호출 위치: order 처리 단계 마지막에 동기로 부른다(read 2초, 최대 3회). 실패해도 주문은 성공이다
- 수동 지정 전환: 횟수 대신 확정 뒤 60초(`delivery.confirmation.manual-assignment-after`). 횟수로 세면 주문이 몰릴 때 너무 빨리 넘어간다. 전환 시각은 `manual_assignment_requested_at`에 남긴다
- ② MASTER 알림: 기존 채널 Webhook(MASTER 목록 API가 필요 없다)
- ③ DM 업체명: company I-07 재조회, 실패하면 이름 없이 보낸다
- 취소된 배송: 취소하면 구간이 `CANCELED`가 되고 배정 대기 조회는 `WAITING` 구간만 고르므로 배정하지 않는다(코드 확인)
- 취소 DM, MASTER 화면의 수동 지정 필요 목록: 후속으로 미룬다
