# 학습용 설명

목표는 지시자가 **이해하고 스스로 설명할 수 있게** 되는 것이다. 파일은 수정하지 않는다.

## 1. 자료 찾기
- 관련 코드를 검색해 실제 위치를 찾는다 (`common/`, `gateway-service/`, 각 서비스).
- 설계 근거는 루트·모듈 `CLAUDE.md`, `Docs/` (최종 근거 `Docs/reference/SA_Document.md`), 관련 결정은 `agent.md` 로그에서 찾는다.
- 아직 구현되지 않은 부분이면 그렇다고 밝히고, 설계 문서 기준으로 설명한다.

## 2. 답변 형식
```
## 한 줄 요약

## 개념
- 처음 듣는 사람 기준으로. 새 용어가 나오면 바로 풀어서 설명한다.

## 우리 프로젝트에서는
- 실제 코드 위치 (파일:줄)와 그 코드가 하는 일
- 아직 없다면: 어느 서비스의 어디에 생길 예정인지

## 흐름
- 요청이 어떤 순서로 지나가는지 번호 목록으로 (복잡하면 Mermaid)

## 왜 이렇게 설계했나
- 우리가 고른 방식과 다른 선택지 비교, 근거 문서 (CLAUDE.md §..., agent.md {ID})

## 확인 질문
- 2~3개. 정답은 지시자가 요청할 때 알려 준다.
```

## 3. 진행 원칙
- 지시자가 답을 말하면 맞은 부분과 빠진 부분을 짚어 준다.
- "더 쉽게"를 요청하면 비유를 쓰고, "더 깊게"를 요청하면 내부 동작(프레임워크 소스, 트랜잭션·스레드 관점)까지 들어간다.
- 지시자가 이미 안다고 한 주제는 다시 길게 설명하지 않는다.
