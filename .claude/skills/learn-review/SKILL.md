# 학습용 코드 리뷰

목표는 지시자가 **스스로 고치면서 배우는 것**이다. 지시자가 요청하기 전에는 파일을 수정하지 않는다.

## 1. 대상과 기준
- 대상: 인자로 받은 경로. 없으면 커밋 전 변경분(`git diff`, `git diff --staged`)과 새 파일.
- 기준: 루트 `CLAUDE.md`, 해당 모듈 `CLAUDE.md`·`agent.md`의 API 계약, `Docs/03-API.md` 명세.
- 우선 확인할 것: 계층 의존 방향, Entity 노출, 논리 삭제·`@SQLRestriction`, 응답 래핑, 페이징, `@MasterOnly`·소유자 검증, 상태 전이 위치, 트랜잭션 경계, Feign 타임아웃·재시도·멱등, 에러 코드.

## 2. 결과 형식
심각도 순서로 묶는다. 항목마다 **위치 · 무엇이 걸리는지(질문형 힌트) · 관련 규칙**만 쓰고 정답 코드는 쓰지 않는다.
```
## 반드시 고칠 것 (규칙 위반·버그)
1. {파일:줄} — 힌트: "이 메서드가 논리 삭제된 행도 조회하지 않을까?" (루트 CLAUDE.md §3-6)

## 고려해 볼 것 (설계·가독성)

## 잘한 점
- 1~3개. 왜 좋은지 함께.
```

## 3. 힌트 단계
지시자가 요청할 때만 다음 단계로 간다.
1. **힌트**: 질문으로 문제 지점만 가리킨다 (기본)
2. **방향**: "무엇을 어떻게 바꾸면 되는지"를 말로 설명한다 ("더 힌트", "모르겠어")
3. **정답**: 수정 코드 예시를 보여 준다 ("정답", "코드로 보여줘")
4. **적용**: 지시자가 명시적으로 요청하면 파일을 직접 고친다

## 4. 다시 보기
지시자가 고친 뒤 다시 리뷰를 요청하면 이전 항목별로 해결 / 미해결 / 새로 생긴 문제를 표시한다.
