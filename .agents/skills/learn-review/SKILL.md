# learn-review: 학습용 코드 리뷰

목표는 사용자가 스스로 고치면서 배우는 것이다. 사용자가 요청하기 전에는 파일을 수정하지 않는다. 원본은 KMH 브랜치의 같은 스킬이다.

## 1. 대상과 기준
- 대상: 인자로 받은 경로. 없으면 커밋 전 변경분(`git diff`, `git diff --staged`)과 새 파일.
- 기준: `docs/guides/review-checklist.md`, 고친 계층의 `docs/agents/rules/*.md`, 모듈 `AGENTS.md`, 서비스 협업 창구의 API 계약, SA.
- 먼저 볼 것: 계층 의존 방향, Entity 노출, 논리 삭제와 `@SQLRestriction`, 응답 형식(외부 `ApiResponse`, 내부 DTO), 정렬 허용 목록, `@RequireRole`과 소유자 검증, 상태 전이 위치, 트랜잭션 경계, Feign 재시도와 멱등성, 에러 코드.

## 2. 결과 형식
심각도 순서로 묶는다. 항목마다 위치, 질문 형태의 힌트, 관련 규칙만 쓰고 정답 코드는 쓰지 않는다.
```
## 반드시 고칠 것 (규칙 위반, 버그)
1. {파일:줄} — 힌트: "이 조회가 논리 삭제된 행도 가져오지 않을까?" (rules/repository.md 논리 삭제)

## 고려해 볼 것 (설계, 가독성)

## 잘한 점
- 1~3개. 왜 좋은지 함께.
```

## 3. 힌트 단계
사용자가 요청할 때만 다음 단계로 간다.
1. 힌트: 질문으로 문제 지점만 가리킨다(기본).
2. 방향: 무엇을 어떻게 바꾸면 되는지 말로 설명한다("더 힌트", "모르겠어").
3. 정답: 수정 코드 예시를 보여 준다("정답", "코드로 보여줘").
4. 적용: 사용자가 명시적으로 요청하면 파일을 고친다.

## 4. 다시 보기
사용자가 고친 뒤 다시 리뷰를 요청하면 이전 항목마다 해결, 미해결, 새로 생긴 문제를 표시한다.
