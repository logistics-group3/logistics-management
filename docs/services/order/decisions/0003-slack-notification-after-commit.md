# 0003. Slack 알림: 커밋 후 비동기 이벤트

- 상태: 제안
- 날짜: 2026-10-14
- 결정자: 최승근 (원문 작성). 팀 승인 기록 없음
- 원문: Notion "스파르타물류 기술 결정 문서 (ADR)" ADR-14, 원문 상태 "확정". 본문은 원문 문장을 그대로 옮겼다
- SA v2.0과의 차이: 없음. SA v2.0은 주문 생성 시 Slack 알림을 요구하고 보내는 방식은 정하지 않았다.

## 맥락
- 주문이 만들어지면 담당자에게 Slack으로 알려야 합니다. Slack은 우리가 통제할 수 없는 외부 서비스이고, 느리거나 실패할 수 있습니다.
- 알림은 부가 기능입니다. 알림 때문에 주문이 실패해서는 안 됩니다.

## 결정
주문 저장 트랜잭션에서 Spring 이벤트를 발행하고, `@TransactionalEventListener(phase = AFTER_COMMIT)` + `@Async` 리스너가 Slack Webhook을 호출합니다. 알림이 실패해도 주문은 유지되고, 예외는 리스너 안에서 잡아 로그만 남깁니다.

## 검토한 대안
| 선택지 | 장점 | 단점 |
|---|---|---|
| 트랜잭션 안에서 직접 호출 | 단순 | 롤백돼도 알림은 이미 발송, Slack이 느리면 DB 커넥션을 잡고 기다림 |
| @EventListener | 코드 분리 | 커밋 전에 실행돼 위와 같은 문제 |
| AFTER_COMMIT (동기) | 커밋된 주문만 알림 | 응답 스레드가 Slack을 기다려 주문 응답이 느려짐 |
| **AFTER_COMMIT + @Async (채택)** | 커밋된 주문만, 응답을 막지 않음 | 서버가 죽으면 알림 유실 |
| 아웃박스 / Kafka | 알림 전달 보장 | 테이블·폴러·브로커 필요 (고도화) |

## 결과
### 이유
- 커밋 후에 보내므로 "없는 주문에 대한 알림"이 생기지 않습니다. 보상으로 롤백된 주문은 이벤트가 버려집니다.
- 비동기로 보내므로 Slack이 느려도(최대 read 20초) 주문 응답은 기다리지 않습니다.
- 알림은 유실돼도 사업에 치명적이지 않아, 아웃박스까지는 과하다고 판단했습니다.

### 트레이드오프
- 커밋 직후 서버가 죽거나 Slack 호출이 실패하면 알림은 사라집니다. ERROR 로그로만 남습니다.
- AFTER_COMMIT 리스너에서 DB에 쓰려면(예: 발송 이력) 원래 트랜잭션이 이미 끝났으므로 `REQUIRES_NEW`가 필요합니다.
- @Async는 전용 스레드 풀(ThreadPoolTaskExecutor, 크기·큐 제한)을 지정해, 알림이 몰려도 다른 비동기 작업을 막지 않게 합니다.
- Spring 이벤트는 같은 JVM 안에서만 전달됩니다. 서비스 간 이벤트에는 쓸 수 없습니다.

## 면접 답변
> "알림은 부가 기능이라 주문 성공에 영향을 주면 안 됩니다. 커밋된 주문만 알리도록 AFTER_COMMIT을, 응답을 막지 않도록 @Async를 썼고, 유실 가능성은 감수했습니다. 전달을 보장해야 한다면 아웃박스 패턴으로 갑니다."
- **Q. AFTER_COMMIT 리스너에서 예외가 나면요?** 이미 커밋됐으므로 주문은 롤백되지 않습니다. 다만 동기 리스너라면 예외가 호출자에게 전파돼 성공한 주문에 에러 응답이 나갈 수 있어, 리스너 안에서 예외를 잡습니다.
- **Q. 아웃박스 패턴이란?** 주문과 같은 트랜잭션에 "보낼 메시지"를 테이블로 저장하고, 별도 프로세스가 읽어 보내는 방식입니다. 주문과 메시지의 저장이 원자적이라 유실이 없습니다.
