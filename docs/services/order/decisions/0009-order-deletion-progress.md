# 0009. 주문 삭제 가능 여부와 진행 기록 보존

- 상태: 채택 (주문 담당자)
- 날짜: 2026-10-15
- 결정자: Junhyun An, "삭제 기록 포함, 끝까지 진행"으로 구현·검증·커밋 승인
- 결정 범위: O-06 기본 명세를 마무리할 때 필요한 주문 내부 실패 처리

## 맥락

SA 6.7의 O-06은 MASTER가 취소된 주문 또는 배송 완료 주문을 논리 삭제한다. 성공은 200, data는 null이다.
SA 7.5는 주문 논리 삭제와 I-13을 한 트랜잭션 메서드에서 수행하고, 주문 커밋 실패는 멱등 I-13 재시도로 수렴시키도록 정한다.

배송 완료 주문에서 I-13 성공 후 주문 DB가 롤백되면 배송만 삭제된 상태가 남을 수 있다. 다시 I-10을 조회하면 404여서 이전에 확인했던 DELIVERED 조건을 복원할 수 없다.
404만 보고 모든 ORDERED 주문을 삭제하도록 허용하면 잘못된 참조·미확정 배송을 삭제 가능으로 오인할 수 있다.

## 결정

1. 공개 O-06 URL·권한·삭제 조건·성공 응답을 유지한다. I-10·I-13은 기존 SA 계약을 사용하며 다른 서비스 소스·API를 바꾸지 않는다.
2. 삭제 조건과 미해결 취소 기록을 확인한 뒤 p_order_deletions에 주문·배송 ID, 진행 상태와 Audit를 별도 커밋한다. 주문 ID는 UNIQUE이며 같은 order_schema의 주문을 참조한다.
3. 취소 상태는 주문에서, 배송 완료는 I-10의 deliveryId·orderId·DELIVERED를 확인한다. 최초 조회 404를 삭제 허가로 취급하지 않는다.
4. 삭제 실행은 같은 주문 행을 잠가 중복 삭제·새 취소와 직렬화한다. SA 7.5에 따라 논리 삭제·I-13·완료 기록을 하나의 트랜잭션 메서드로 처리한다.
5. I-13 또는 주문 커밋 결과가 불확실하면 진행 기록을 보존한다. MASTER의 같은 주문 삭제 재요청은 저장된 삭제 조건을 근거로 I-13을 다시 호출할 수 있다. 없음·이미 삭제인 배송은 기존 I-13 계약대로 204다.
6. 주문 논리 삭제와 완료 기록이 같은 커밋으로 확인되면 성공을 유지한다. 자동 스케줄러나 배송 복원 API는 추가하지 않는다.
7. 미해결 삭제가 있으면 새 취소를 막는다. 생성 멱등키와 최초 응답은 삭제 이후에도 유지한다.

진행 상태는 PROCESSING·COMPLETED·RECOVERY_REQUIRED로 구분한다. 성공한 I-13을 원복하는 계약이 없으므로 미확정 삭제를 자동 중단 처리하지 않는다.
V5·도메인·서비스를 이 결정에 따라 구현한다. 전용 운영 복구 API와 생성 진행 조회는 이번 기본 기능 마무리 범위에 포함하지 않는다.

## 검토한 대안

- 기록 없이 현재 SA 순서만 구현: CANCELED 주문은 재시도할 수 있지만 ORDERED·DELIVERED 주문의 삭제 허가 근거를 잃을 수 있다.
- I-10의 404면 삭제 허용: 삭제가 이미 수행된 경우와 잘못된 참조·기존 누락을 구분하지 못한다.
- 배송 조회에 삭제 이력까지 반환하도록 변경: 제공 서비스의 새 계약·권한·구현 합의가 필요하다.
- 삭제의 원격 호출도 전부 트랜잭션 밖으로 분리: 실행권과 장애 복구 설계가 더 커진다. 이번에는 기존 SA 7.5의 잠금·트랜잭션 경계를 유지한다.

## 검증 결과와 비용

- 일반 사용자 403, 없음·삭제 404, 삭제 불가 409, 취소·배송 완료 삭제 200을 확인했다.
- I-10·I-13 오류, 로컬 flush·커밋 실패, 배송 삭제 후 재요청, 동시에 들어온 삭제와 새 취소 차단을 실제 PostgreSQL·HTTP 대역으로 검증했다. 주문 421개·전체 XML 519개와 전체 build가 통과했다.
- I-13은 요청당 1회 호출하고 정확한 204를 확인한다. 200·202는 완료로 오인하지 않으며 생성 실패 보상의 기존 최대 3회 정책은 유지한다.
- 삭제 조건 확인 기록이 남으므로 실패 뒤 다시 GET으로 배송 완료를 증명하지 않아도 같은 삭제를 계속할 수 있다.
- 원격 호출 동안 주문 잠금과 DB 연결을 사용한다. 이 비용과 기존 Feign/Gateway 시간 예산은 문서에 명시하며 공통 타임아웃은 변경하지 않는다.
- 실제 company·delivery와의 통합, 지연 생성 종료 보장(DELIVERY-002), 자동 복구·Outbox는 별도 남은 작업이다.
