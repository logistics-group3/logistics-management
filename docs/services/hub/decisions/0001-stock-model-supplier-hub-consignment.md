# 0001. 재고 모델: 공급업체 허브 1곳의 위탁 재고

- 상태: 제안
- 날짜: 2026-10-14
- 결정자: 최승근 (원문 작성). 팀 승인 기록 없음
- 원문: Notion "스파르타물류 기술 결정 문서 (ADR)" ADR-06, 원문 상태 "확정". 본문은 원문 문장을 그대로 옮겼다
- SA v2.0과의 차이: 원문은 재고를 기본 범위로 두고 공급업체 허브 1곳의 재고만 확인·차감한다. SA v2.0은 특정 업체 상품의 재고를 무한으로 가정하고 재고 관리 전체를 고도화로 둔다(1.3, 설계 결정 9).

## 맥락
- 원본 SA는 재고를 무한으로 가정했습니다. 그러면 주문 Saga에 "실패할 수 있는 쓰기"가 배송 생성 하나뿐이라, 보상·동시성 설계가 드러나지 않습니다.
- 또 주문마다 "업체 → 허브 집하"를 기록하면, 이미 허브에 있는 재고를 다시 집하하는 모순이 생깁니다. 그래서 입고(업체 → 허브)를 주문과 분리했습니다.
- SA와 다른 부분은 서비스 담당자가 채택 여부를 결정한다.

## 결정
재고는 기본 범위입니다. 업체가 소속 허브에 입고한 수량만 팔 수 있고, 주문은 공급업체 허브 1곳의 재고만 확인·차감합니다. 재고 레코드는 첫 입고 때 만들고, 허브 재고는 팔리기 전까지 업체 소유(위탁)로 봅니다.

## 검토한 대안
| 선택지 | 장점 | 단점 |
|---|---|---|
| 무한 재고 (원본) | 구현 단순 | 보상·동시성을 보여줄 수 없고 현실과 다름 |
| **공급업체 허브 1곳 (채택)** | 재고 판단이 행 1개로 끝남, 교착 없음 | 다른 허브에 재고가 있어도 못 판 |
| 여러 허브 재고 모아 출고 | 재고 활용도 높음 | 여러 행 잠금·교착, 배송이 여러 갈래로 나뉠 (고도화) |

| 재고 레코드 생성 시점 | 장점 | 단점 |
|---|---|---|
| 상품 생성 시 수량 0으로 | 주문 시 항상 레코드 존재 | 상품 생성에도 company → hub 호출과 실패 처리가 필요 |
| **첫 입고 때 (채택)** | 상품 생성이 company 안에서 끝남 | 레코드 없는 상품 주문을 409로 처리해야 함 |

## 결과
### 이유
- 업체의 관리 허브는 고정이므로(M9) "어느 허브 재고를 쓸지"가 항상 하나로 정해집니다. 주문 1건이 다루는 재고 행이 1개라 동시성 문제가 단순해집니다(ADR-08).
- 레코드를 첫 입고 때 만들면, "입고한 적 없는 상품"과 "다 팔린 상품"을 모두 재고 부족(409)으로 똑같이 다루면 됩니다. 상품 생성에 서비스 간 호출이 생기지 않습니다.
- **정산은 주문(판매) 기준**을 전제로 합니다. 업체가 상품을 직접 등록·삭제·입고하므로, 입고 시점에 물류사가 물건을 사는 매입형보다 팔릴 때까지 업체 소유인 위탁형이 도메인과 맞습니다. 매입형이면 업체가 상품을 지울 때 물류사가 팔 수 없는 재고를 떠안습니다. 정산 기능 자체는 범위 밖입니다.
- 재고 변동은 모두 이력 테이블(INBOUND / DECREASE / RESTORE)에 남깁니다. `(재고 ID, orderId, 변동 유형)` 유니크 제약이 차감·복원의 멱등키이고, 나중에 주문 기준 정산의 근거 데이터가 됩니다.

### 트레이드오프
- 다른 허브에 재고가 남아도 주문은 실패합니다. 업체가 허브 한 곳에만 소속되므로 이번 범위에서는 생기지 않는 경우입니다.
- 입고는 멱등키가 없어, 응답을 못 받고 다시 보내면 두 번 입고될 수 있습니다. 그래서 자동 재시도를 하지 않습니다. 필요하면 클라이언트가 요청 ID(Idempotency-Key)를 보내는 방식을 추가합니다.
- 반출(업체가 재고를 돌려받기)과 재고 조정(분실·파손)은 범위 밖입니다.

## 면접 답변
> "재고를 무한으로 두면 분산 트랜잭션의 핵심인 보상과 동시성을 다룰 일이 없어서 기본 범위로 끌어왔습니다. 다만 여러 허브를 섞으면 교착과 배송 분할 문제가 생겨, 공급업체 허브 한 곳만 보도록 범위를 줄였습니다."
- **Q. 재고 숫자는 무엇을 뜻하나요?** 허브에 실제로 있는 업체 물건의 수량입니다. 그래서 주문이 취소되거나 상품이 삭제돼도, 실물이 남아 있는 한 수량을 지우지 않습니다(ADR-13).
- **Q. 입고 기준으로 정산하면 무엇이 문제인가요?** 입고 순간 소유가 물류사로 넘어가므로, 업체가 상품을 지우면 물류사가 팔 수 없는 재고를 산 셈이 됩니다. 업체가 상품을 마음대로 지울 수 있는 지금 설계와 맞지 않습니다.
