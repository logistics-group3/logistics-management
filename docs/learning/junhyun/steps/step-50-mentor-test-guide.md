# 50. 멘토 테스트 가이드 화면과 시나리오 데이터

- 날짜: 2026-10-16
- 브랜치: `feat/infra-monitoring-mentor-guide`
- 이번 커밋 제목: `feat(ui): 멘토 테스트 가이드 화면과 시나리오 데이터 추가`
- 범위: 사용자 요청 "프론트에 멘토님이 편하게 테스트할 수 있도록 가이드 및 절차, 테스트 데이터 다 넣어줘". 기준은 발제문 필수 기능 가이드다(팀 Notion "발제문 원본"). 기대 결과는 SA가 아니라 실제 서버 동작으로 적고, 발제와 다른 점은 화면에 따로 밝힌다.

## 바뀐 동작

- 운영 콘솔 `/guide`가 생겼다.
  - 로그인 전에는 사이드바 없는 화면, 로그인 후에는 사이드바 "멘토 테스트 가이드"로 연다.
  - 테스트 환경 링크: Swagger, Grafana, Zipkin, Prometheus, Eureka
  - 테스트 계정 6개와 각 계정으로 확인할 내용
  - 발제 영역별 시나리오 20개: 절차, 기대 결과, 발제 항목. 서버 기능이 없는 2개는 "구현 대기"로 표시한다
  - 현재 범위와 발제와 다른 점
- 시나리오의 "uiuser로 시작" 같은 버튼은 그 계정으로 로그인한다(다른 계정이면 바꾼다). 그 뒤 시나리오 화면(예: `/orders/new`)으로 바로 간다.
- 카드의 확인 표시와 "n / 20 확인 완료"는 그 브라우저의 localStorage에만 남는다.
- 로그인 화면에 "테스트 계정 입력"이 생겼다. 버튼은 아이디·비밀번호만 채우고 제출은 사용자가 한다.
- 배송담당자가 없어 주문이 실패하면(404 `DELIVERY_MANAGER_NOT_FOUND`) 일반 404 문구 대신 전용 안내가 나온다. "배송을 만들지 못했고, 주문도 남기지 않았다"는 뜻을 전한다.
- `script/ui-test.sh seed`가 데이터를 더 만든다.
  - 경기 북부·부산 배송담당자(`uidrvgg`, `uidrvbs`)
  - 발제 예시 업체: 경기 건조식품 가공 → 부산 수산 도매, 마른오징어 가공품
  - 롤백 시나리오용 대전 업체 2곳과 상품. 대전 허브에는 배송담당자를 두지 않는다
  - 다시 실행해도 중복되지 않는다. 식별자는 `.local/ui-test-data.json`의 `scenario`에 남는다

## 왜 이렇게 만들었는가

- **기대 결과를 실제 동작으로 쓴 이유**: 멘토는 발제와 화면을 비교한다. 문서와 화면이 다르면 신뢰를 잃는다. 모든 기대 결과를 API로 먼저 확인했다(대전 주문 404·주문 수 그대로, 다른 허브 담당자 403, 다른 사람 주문 403, 없는 허브 업체 404 `HUB_NOT_FOUND`, 다른 업체 수정·상품 등록 403, 사용자 검색 403, 경로 API 404).
- **새 배송담당자를 서울에 두지 않은 이유**: 자동 배정은 허브의 담당 건수가 가장 적은 담당자를 고른다. 서울에 늘리면 기존 E2E의 `uidriver` 배정이 바뀐다.
- **E2E를 고친 이유**: "MASTER 배송담당자 지정" 테스트는 "서울이 아닌 첫 허브"를 골랐다. 그 허브(부산)에 시드 담당자가 생기자 새 담당자가 유일한 후보가 아니게 돼 실패했다. 테스트가 숨기고 있던 전제("그 허브에 다른 담당자가 없다")를 코드로 드러냈다. 담당자가 있는 허브와 롤백용 허브는 고르지 않는다.
- **롤백 시나리오를 대전 허브로 만든 이유**: 발제 필수 구현 범위의 "실패 시 롤백 시나리오"를 화면에서 바로 재현할 수 있어야 한다. 담당자가 없으면 배송 생성이 404로 끝나고, 주문 Saga가 주문을 남기지 않는다(ABORTED 기록만 남음).
- **계정 버튼이 로그인까지 하는 이유**: 멘토가 계정 6개를 오가며 권한 차이를 보는 일이 대부분이다. 로그인 화면 버튼은 입력만 채워 기존 로그인 흐름과 E2E 선택자를 바꾸지 않는다.
- **비밀번호를 화면에 보이는 이유**: 전용 테스트 DB에만 있는 공개 예제 계정이고 README에도 있다. 실제 서비스 계정이 아니다.

## 검증 결과

- 프런트:
  - `npm run build` 성공, `lint`·`format:check` 통과
  - 단위 테스트 46개 통과. 새 테스트 5개: 시나리오 ID 중복, 계정 존재, 경로 규칙, 링크 주소, 404 안내
- 시드: UI 테스트 스택에서 실행하고 다시 실행했다. 계정 7명(직접 가입한 1명 포함), 업체 8개, 새 업체 중복 없음
- 화면(Chrome) 확인 항목:
  - 공개 `/guide`가 열리고, "uiuser로 시작"을 누르면 로그인 후 새 주문 화면이 열린다
  - 사이드바 링크로 가이드를 연다
  - "uimaster로 시작"을 누르면 계정이 바뀐다
  - 대전 주문은 404 `DELIVERY_MANAGER_NOT_FOUND`이고 주문 13건이 그대로다
  - 로그인 화면 계정 입력 후 로그인된다
  - 390px 폭에서 가로 스크롤이 없다
- E2E:
  - 기존 15개는 허브 선택 조건을 고친 뒤 15개 모두 통과했다
  - 가이드 2개(접근성 포함)는 색 대비를 고친 뒤 통과했다. 처음 실행 때 axe가 작은 회색 글씨의 대비 부족(4.5:1 미만)을 잡아 #56676f로 바꿨다
  - 색 대비 수정 뒤 전체 17개를 한 번에 다시 돌리지는 않았다
- 실제 DM이 켜진 UI 테스트 환경이라 검증 동안 `.env.ui-test`의 `SLACK_DM_ENABLED`를 false로 바꿨다(문서 절차). 끝난 뒤 원래 값으로 되돌린다
- 미확인: 다른 허브 간 주문 시나리오(hub I-03 미구현), 실제 Slack 발송(테스트에서 끔)

## 직접 해보기

1. `script/ui-test.sh up`, `script/ui-test.sh seed`, `script/ui-test.sh frontend`를 차례로 실행한다.
2. 로그아웃 상태에서 http://127.0.0.1:5174/guide 를 연다. 계정 표와 시나리오 카드가 보이면 성공이다.
3. "배송을 만들 수 없으면 주문도 남지 않는다" 카드의 "uimaster로 시작"을 누른다. 대전 업체·서류 보관함으로 주문하면 전용 안내와 `HTTP 404 · DELIVERY_MANAGER_NOT_FOUND`가 나온다. 주문 목록 건수가 그대로인지 본다.
4. "배송 구간은 담당자 본인…" 카드로 uidriver 처리 뒤, 가이드에서 uidrvgg로 바꿔 같은 배송 주소를 열어 403을 본다.
5. Grafana(13000)의 "주문 생성 응답"에 404가 늘었는지 본다.

## 확인 질문

- 테스트 데이터를 추가할 때 기존 E2E가 깨질 수 있는 경로는 무엇이었나(자동 배정 후보, 허브 선택)
- 롤백 시나리오에서 주문은 왜 남지 않나(Saga 생성 기록 ABORTED, 주문 저장 전 배송 실패)
- 화면에서 권한 버튼을 숨기는 것과 서버 인가는 어떻게 다르고, 왜 둘 다 확인하나
