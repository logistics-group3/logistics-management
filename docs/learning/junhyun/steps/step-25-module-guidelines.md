# 스텝 25. 모듈별 지침

- 날짜: 2026-10-14
- 근거: Notion "docs·AI 지침 통합 방안" 4.1(KMH의 모듈별 CLAUDE.md 배치)과 6장 결정("agent.md는 각 모듈 작업자들을 위한 지침", 도구 중립 정본)
- 결과: 모듈 10개에 `AGENTS.md`(정본)와 `CLAUDE.md`(`@AGENTS.md` 한 줄)

## 바꾼 것
| 파일 | 내용 |
|---|---|
| `{module}/AGENTS.md` ×10 | 책임과 경계, 작업 전에 읽을 것, 모듈 규칙, 다른 모듈이 필요할 때, 검증 |
| `{module}/CLAUDE.md` ×10 | `@AGENTS.md` 한 줄. Claude Code가 그 폴더 파일을 다룰 때 같은 지침을 읽는다 |
| 루트 `AGENTS.md` | 시작 절차에 "고칠 모듈의 AGENTS.md를 먼저 읽는다", 작업별 필수 문서 표에 레이어 규칙·협업 창구·에러 코드·리뷰 체크리스트·작성 가이드 |

## 리뷰 포인트
1. **정본은 AGENTS.md**: Codex는 `AGENTS.md`를 읽고, Claude Code는 `CLAUDE.md`를 읽는다. 내용을 `AGENTS.md`에만 쓰고 `CLAUDE.md`는 가져오기만 하면 두 도구가 같은 지침을 본다(ADR 0002).
2. **하위 지침을 직접 읽게 한 이유**: 에이전트마다 하위 폴더 지침을 읽는 시점이 다르다. 루트 `AGENTS.md` 시작 절차에 "모듈 AGENTS.md를 먼저 읽는다"를 넣어 도구와 관계없이 같은 순서가 되게 했다(KMH 규칙 1).
3. **KMH 원본과 다른 점**: KMH는 모듈 폴더에 `CLAUDE.md`(세부 규칙)와 `agent.md`(협업 창구)를 나눠 뒀다. 여기서는 규칙만 모듈 `AGENTS.md`에 두고, 협업 창구는 `docs/services/`로 옮겼다(스텝 24). KMH 원문은 이전 SA 기준이라 규칙은 SA v2.0에서 다시 뽑았다.
4. **"다른 모듈은 직접 고치지 않는다"**: KMH 규칙 2를 그대로 가져왔다. 필요한 변경은 그 서비스 협업 로그에 `OPEN`으로 요청한다.

## 서비스 담당자가 할 일
- 도메인을 구현하면서 생긴 모듈 규칙(상태 전이 세부, 컬럼 길이 등)을 자기 모듈 `AGENTS.md`에 추가한다.
