# Saga와 분산 트랜잭션은 무엇이 다르고 보상 트랜잭션은 분산이 아닌가

## 질문
Saga 패턴을 쓰면 분산 트랜잭션을 안 쓰는 건가. Saga와 분산 트랜잭션은 무엇이 다른가. 보상 트랜잭션은 분산이 아닌가.

## 짧은 답
- 좁은 뜻의 **분산 트랜잭션**은 여러 DB·서비스를 하나의 원자적 트랜잭션으로 묶는 것이다(2PC, XA). Saga는 이것을 **쓰지 않는다**.
- Saga는 **서비스마다 로컬 트랜잭션을 따로 커밋**하고, 중간에 실패하면 **이미 커밋된 일을 되돌리는 별도 호출(보상)** 을 보낸다.
- 보상 트랜잭션도 **로컬 트랜잭션**이다. 그 서비스 자기 DB 안에서 끝나는 일반 커밋이다. 흐름 전체는 여러 서비스에 걸치지만, 그 전체가 원자적이지는 않다.
- 일상 용어로 "여러 서비스에 걸친 작업의 일관성 문제"를 분산 트랜잭션이라 부르기도 한다. 그 넓은 뜻에서는 Saga도 그 문제를 푸는 패턴이다. **2PC 같은 원자적 커밋 프로토콜을 쓰느냐**로 구분하면 정확하다.

## 자세히

### 1. 무엇이 다른가
| 항목 | 분산 트랜잭션(2PC/XA) | Saga |
|---|---|---|
| 커밋 단위 | 모든 참여자를 한 번에 커밋 또는 롤백 | 서비스별 로컬 커밋을 차례로 수행 |
| 원자성 | 전체가 원자적 | 전체는 원자적이지 않다. 보상으로 **결과적으로** 되돌린다 |
| 격리성 | 커밋 전까지 다른 트랜잭션에 안 보인다 | 중간 상태가 **다른 요청에 보인다**(커밋이 이미 끝났으므로) |
| 되돌리는 방법 | DB가 롤백한다 | 애플리케이션이 반대 동작을 호출한다(배송 삭제 등) |
| 잠금 | 준비 단계부터 끝까지 유지 | 로컬 트랜잭션 동안만 유지 |
| 장애 | 코디네이터 장애 시 참여자가 잠긴 채 대기할 수 있다 | 보상이 실패할 수 있다. 이 상태를 별도로 관리해야 한다 |
| 요구 조건 | 모든 참여자가 XA 같은 프로토콜 지원 | 각 서비스가 멱등한 API와 보상 API 제공 |

Saga는 ACID에서 **격리성(I)을 포기**하고 원자성은 보상으로 흉내 내는 방식이다. 그래서 설계자가 중간 상태와 보상 실패를 직접 다뤄야 한다.

### 2. 보상 트랜잭션은 분산인가
- 보상 하나하나는 **분산이 아니다**. delivery가 자기 DB에서 배송을 지우는 로컬 커밋이다.
- 흐름 전체(생성 → 저장 → 실패 → 보상)는 여러 서비스에 걸쳐 있으므로 **분산된 작업**이다. 하지만 그 전체를 하나의 트랜잭션으로 묶지는 않는다.
- 보상은 **진짜 롤백이 아니다.** 이미 커밋돼 다른 사람이 읽었을 수 있는 데이터를 반대 방향으로 고치는 새 변경이다. 롤백은 처음부터 없던 일이 되지만 보상은 이력이 남는다.

### 3. 이 프로젝트에서의 대응
| 개념 | order-service의 구현 |
|---|---|
| 로컬 트랜잭션 | 주문 저장(`OrderWriter`)은 order DB의 독립 트랜잭션이다. delivery의 배송 생성(I-09)은 delivery DB의 커밋이다 |
| 원격 호출 중 트랜잭션 | 잡지 않는다. `OrderService.begin`의 주석: 원격 호출을 DB 트랜잭션 안에 두지 않는다 |
| 보상 | 주문 저장 실패가 확인되면 delivery의 생성 조건부 종료(I-18, `closeCreation`)를 최대 3회 호출한다. 종료 표시가 남으면 늦게 도착한 I-09도 거절된다 |
| 보상 실패·결과 불명 | 지우지 못하거나 결과를 모르면 `RECOVERY_REQUIRED`로 두고 MASTER가 복구한다. 보상이 항상 성공한다고 가정하지 않는다 |
| 중간 상태 | 배송이 생성됐지만 주문 저장 전인 시간이 있다. 그래서 배송 확정(I-19)을 주문 커밋 뒤로 미뤘다 |
| 재시도 안전성 | orderId를 먼저 발급해 생성·확정·삭제를 orderId 기준 멱등으로 만들었다 |

### 4. 정리해서 말하면
"주문 서비스는 2PC 같은 원자적 분산 커밋을 쓰지 않고, 서비스별 로컬 커밋과 보상 호출로 최종 일관성을 맞춘다. 대신 중간 상태가 보이고 보상이 실패할 수 있어서, 멱등성과 복구 상태를 설계에 넣었다."
