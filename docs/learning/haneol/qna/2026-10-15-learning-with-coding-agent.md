# 에이전트와 개발하면서 배우려면 일을 어떻게 나눠야 하나

## 질문
배우려고 왔는데 현업처럼 "다음, 다음"으로 에이전트에게 구현을 맡기니 배우는 게 없는 것 같다. 어떻게 해야 하나.

## 짧은 답
에이전트가 코드를 쓰고 내가 승인만 하면, 결과물은 남아도 판단하는 힘은 남지 않는다. 학습 가치가 큰 부분(도메인 규칙, 트랜잭션, 쿼리)은 내가 먼저 쓰고 에이전트는 힌트와 리뷰만 한다. 반복 작업과 문서는 에이전트에게 맡긴다. 기준은 "면접에서 이 코드를 설명하고 다시 짤 수 있는가"다.

## 자세히

### 왜 "다음, 다음"은 남는 게 없나
- 학습은 막히고, 틀리고, 고치는 과정에서 생긴다. 에이전트가 처음부터 맞는 코드를 주면 그 과정이 통째로 빠진다.
- 읽고 이해한 것과 직접 만들 수 있는 것은 다르다. 리뷰만 하면 "본 적 있는" 수준에 머문다.
- 결정도 에이전트가 먼저 제안하면 내가 고르는 일만 남는다. 선택지를 스스로 떠올리는 힘이 자라지 않는다.

### 일을 나누는 기준
| 내가 직접 | 에이전트에게 맡김 |
|---|---|
| 도메인 규칙(상태 전이, 불변식) | 문서 동기화, 기록, 커밋 정리 |
| 트랜잭션 경계, 동시성, 멱등성 | 반복되는 DTO, 매핑, 설정 |
| 핵심 쿼리(배정, 권한 필터 검색) | 이미 한 번 직접 해 본 패턴의 반복 |
| 테스트 시나리오 정하기 | 테스트 보일러플레이트 |

### 직접 할 때의 순서
1. 무엇을 만들지 내가 먼저 말로 설명한다(입력, 출력, 실패 조건).
2. 실패하는 테스트를 먼저 쓴다.
3. 구현한다. 막히면 에이전트에게 정답이 아니라 힌트를 요청한다. 힌트 → 부분 코드 → 전체 코드 순서다.
4. 다 되면 `learn-review`로 리뷰를 받는다. 에이전트는 바로 고치지 않고 문제를 짚는다.
5. 마지막에 "왜 이렇게 했나"를 내 말로 써 본다. 막히는 곳이 아직 모르는 부분이다.

### 에이전트가 구현한 부분을 내 것으로 만드는 법
- 커밋 전에 diff를 한 줄씩 읽고, 모르는 줄은 질문한다.
- 에이전트가 낸 "생각해 볼 질문"에 직접 답한다.
- 같은 코드를 보지 않고 다시 짜 본다(progress 파일의 "직접 해보기").

## 이 프로젝트에서는
- 루트 `AGENTS.md` 대전제 5: 사용자가 "내가 할게"라고 하면 에이전트는 단계 안내와 리뷰만 한다.
- `docs/agents/learning-guide.md` 3절: 힌트 → 부분 코드 → 전체 코드 순서로 돕는다.
- `learn-review` 스킬: 직접 쓴 코드를 바로 고치지 않고 힌트부터 준다.
- delivery T01의 다음 단계인 상태 전이(`Delivery`의 구간 출발·도착, 취소)는 배송의 핵심 규칙이라 직접 구현하기 좋은 대상이다.

## 면접 포인트
- "AI 도구를 어떻게 썼나요?": 핵심 도메인 로직과 테스트 시나리오는 직접 짜고, 반복 작업과 문서화는 도구에 맡겼다. 도구가 쓴 코드는 리뷰하고 직접 다시 짤 수 있는지로 이해를 확인했다.
