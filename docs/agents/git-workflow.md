# Git 작업 규칙

> 초안이다. 팀 합의 전까지는 제안 상태로 두고, 합의되면 이 줄을 지운다.

## 브랜치
- `main`: 항상 빌드가 통과하는 상태를 유지한다. 직접 푸시하지 않는다.
- 작업 브랜치: `{이름}/{작업}`. 예: `junhyun/base-setting`, `junhyun/hub-crud`
- 하나의 브랜치는 하나의 작업 단위만 다룬다. 끝나면 PR로 main에 합친다.

## 커밋 메시지
Conventional Commits의 type만 쓰고 scope(괄호)는 쓰지 않는다. 설명은 한국어로 쓴다.
```
<type>: <요약>

<본문: 무엇을, 왜. 필요할 때만>
```
- type: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `build`
- 예: `feat: 허브 간 최단 경로 조회 API 추가`
- `Co-Authored-By` 같은 AI 공동 작성자 표기를 넣지 않는다.
- 요약은 50자 안쪽 평서형으로 쓴다. 마침표를 찍지 않는다.
- 한 커밋에 한 가지 변경만 담는다. 빌드가 깨지는 중간 커밋을 만들지 않는다.

## PR
```
## 작업 내용
## 변경 이유
## 확인 방법 (실행한 명령과 결과)
## 리뷰 포인트
## 관련 문서 (progress, ADR, 학습 노트)
```
- 머지 전에 `./gradlew build` 통과를 확인한다.
- 리뷰어가 볼 만한 `Note:` 주석이 있으면 리뷰 포인트에 적는다.

## 에이전트 규칙
- 사용자가 요청할 때만 커밋하고 푸시한다.
- `main`에서 직접 작업하지 않는다. 브랜치를 먼저 만든다.
- force push, reset --hard, 브랜치 삭제는 사용자 확인 후에만 한다.
