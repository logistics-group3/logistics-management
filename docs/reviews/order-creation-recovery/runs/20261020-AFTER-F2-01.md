## 관찰과 판단

의도한 docker kill 전에 order가 종료돼 container is not running으로 실패했다. 추가 inspect는 OOMKilled=true·exit 137, Docker events는 oom을 기록했다.
실험 중단 조건을 만족하지 못했으므로 F2의 의도한 종료·복구 성공으로 세지 않는다. 기록·시도·배송 데이터는 보존했다.
전용 스택만 내리고 메모리 상한을 적용한 뒤 새 runId로 대조군과 F1/F2를 다시 수행했다. 실제 조치·설정 변경은 TS-031과 전체 결과 문서를 따른다.

## 해석과 환경

같은 허브의 공개 API 주문, 실제 Gateway·Feign·PostgreSQL을 사용했다. 원본 주문을 재생성한 결과가 아니라 안전한 ABORTED 종료다.
-01 실행은 메모리 상한 도입 전, -02는 JVM/컨테이너 상한 적용 후다. 두 환경을 성능 비교에 사용하지 않는다.
복구 API의 최종 요청 정보 조회 필드 보강 뒤 기존 결과를 실제로 다시 조회하고 데이터 상태가 같은지 확인했다.
최종 전용 스택은 종료했고 전용 DB 볼륨·기존 컨테이너 ID·실행 상태를 확인했다. OOM 전후 기존 일부 컨테이너 재시작이 관찰돼 무영향을 주장하지 않는다.
