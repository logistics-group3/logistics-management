# 물류 운영 콘솔 전면 개편 — 2026-10-20

화면을 안내 중심 대시보드에서 주문·배송을 조회하고 다음 업무로 이동하는 운영 콘솔로 개편했다. 기존 API·권한·금액·멱등 요청 계약을 유지했다.
사용자가 현재 브랜치의 프런트 전면 개편을 요청했다. 구현은 이 프런트 PR의 리뷰 대상이며 배포·팀 설계 채택을 뜻하지 않는다.

Madia UI/UX 가이드의 관리 화면 밀도·필터 상태 관점을 적용했다. `make-interfaces-feel-better`의 한국어 줄바꿈·숫자 정렬·표면·초점·모션 기준으로 실제 렌더를 점검했다.
이미지·지연률·GPS 위치·전일 대비 수치 같은 가상 운영 데이터를 추가하지 않았다. 지도·신규 백엔드·새 디자인 라이브러리는 추가하지 않았다.

## 데이터와 동작

- 오늘 접수 주문은 기존 시작일·종료일 조건으로 한국 시간의 당일 건수를 조회한다.
- 배송 8단계는 서버 상태를 그대로 사용한다. 진행 중 지표는 집하 중·허브 대기·허브 이동 중·도착 허브 입고·업체 배송 중의 합계다.
- 기간이 표시되지 않은 배송 지표는 전체 기간·삭제 제외·현재 계정의 권한 범위다. 조회 실패를 0건으로 표시하지 않는다.
- 지표 요청은 각각 실행된다. 전체 수치가 한 DB 트랜잭션의 원자적 스냅샷이라는 보장은 없다.
- 배송 단계와 집하 대기 조치를 누르면 `/deliveries?status=...`로 이동한다. 상태 조건은 실제 API 요청에 적용되고, 상세 패널을 닫아도 유지된다.
- 자동 갱신을 추가하지 않았다. 새로고침 버튼으로 다시 조회하며 대시보드에 조회 기준과 시각을 표시한다.
- 주문 상태와 배송 상태를 섞지 않는다. 인증 토큰의 메모리 보관·원화 정밀도·미확정 주문 요청 보존은 기존 구현을 유지한다.

## 소스 구성

`src/index.css`는 스타일 진입점이다. 기존 단일 CSS를 다음 책임으로 나눴다.

| 파일 | 책임 |
|---|---|
| `frontend/src/styles/base.css` | 공통 토큰·타입·기본 입력·버튼·초점 |
| `frontend/src/styles/workspace.css` | 셸·메뉴·대시보드·목록·상태·반응형 |
| `frontend/src/styles/details.css` | 상세 패널·업체/상품/주문 폼·배송 구간·알림 |
| `frontend/src/styles/auth.css` | 로그인·회원가입 |
| `frontend/src/styles/guide.css` | 멘토 테스트 가이드 |

기본 스타일을 먼저 가져와 모바일 메뉴의 표시 규칙과 충돌하지 않게 했다. 기존 CSS 마지막에 덧붙어 있던 텍스트 대비 보정은 해당 요소의 정의에 반영했다.
대시보드·공통 셸·인증 소개·주문/배송/기준정보 제목을 변경했다. 배송 목록은 URL 상태 필터와 상세 복귀를 연결했으며 이에 대한 E2E를 추가했다.

### 전체 E2E가 통과하지 않은 이유

기존 테스트는 해당 허브의 배송 담당자가 고정되어 있다고 가정한다. 실제 전용 테스트 환경에는 추가 담당자가 등록되어 있어 이 가정과 다르다.
읽기 API로 서울 후보 `dmgr1`, `dmgr2`, `uidriver` 3명, 경기 후보 `dmgr3`, `uidrvgg` 2명, 부산 `uidrvbs` 1명을 확인했다. 기존 후보를 해제하거나 테스트 단언을 약하게 바꾸지 않았다.

| 테스트 | 실제 실패와 확인 |
|---|---|
| 담당자 해제 반영 후 기존 토큰·UI 변경 차단 | UI에 진입하기 전 API 결과에서 모든 구간이 uidriver라는 단언이 실패했다. |
| 경기 → 부산 허브 간 주문·담당자별 처리 | 집하 구간은 uidrvgg가 처리했지만 허브 이동 구간은 다른 담당자에게 배정됐다. 고정 계정으로 다음 출발 버튼을 기다리다 시간 초과했다. 실제 배송의 구간별 담당자를 재조회해 확인했다. |
| 배송담당자의 배정 구간 처리와 세션 만료 | 새 배송 2구간이 모두 uidriver 외 사용자에게 배정됐다. uidriver 화면에서 본인 이름·처리 버튼을 기대하는 전제가 맞지 않았다. |

따라서 전체 E2E 20개 성공으로 보고하지 않는다. 이 3개는 담당자가 고정된 별도 테스트 데이터 또는 실제 배정자를 사용하는 테스트 설계로 후속 검증해야 한다.
이번 작업이 실패한 시나리오에서 만든 주문 2건은 기존 테스트의 종료 절차에 따라 취소 또는 남은 구간 완료 후 삭제했다. [정리 결과](ui-redesign/2026-10-20/test-cleanup.json)에 ID와 HTTP 결과를 남겼다.
기존 사용자·담당자 후보·시드 주문은 이 수동 정리 대상에 포함하지 않았다. 자동 테스트가 생성·정리하는 전용 데이터와 구분한다.
