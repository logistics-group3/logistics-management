# learn-explain — 우리 코드에 연결한 개념 설명

> 분류: 학습 · 절차 원본: [`.claude/skills/learn-explain/SKILL.md`](../../.claude/skills/learn-explain/SKILL.md)

## 목적
그냥 질문하면 AI는 일반론으로 답하기 쉽다. 이 skill은 **우리 프로젝트의 실제 코드 위치와 설계 이유**에 연결해 설명하고, 이해했는지 스스로 확인할 질문을 낸다. 파일은 수정하지 않는다.

## 이럴 때 쓴다
- 처음 보는 개념: "Saga 오케스트레이션이 뭐야?", "`@TransactionalEventListener`는?"
- 남이 짠 코드: "`FeignHeaderInterceptor`는 뭘 하는 거야?"
- 설계 이유: "왜 재고 행을 먼저 잠가?", "왜 Gateway에서만 인증해?"

## 호출
```
/learn-explain FeignHeaderInterceptor
/learn-explain 왜 I-06 복원은 락 없이 먼저 조회해?
```

## 답변 구성
| 순서 | 내용 |
| --- | --- |
| 한 줄 요약 | 핵심을 한 문장으로 |
| 개념 | 처음 듣는 사람 기준, 새 용어는 바로 풀어서 |
| 우리 프로젝트에서는 | 실제 코드 위치(파일:줄)와 하는 일. 아직 구현 전이면 어디에 생길 예정인지 |
| 흐름 | 요청이 지나가는 순서 (복잡하면 Mermaid 그림) |
| 왜 이렇게 설계했나 | 다른 선택지와 비교, 근거 문서(`CLAUDE.md` §, `agent.md` 로그 ID) |
| 확인 질문 | 2~3개. 정답은 요청할 때 |

## 이어서 할 수 있는 말
| 말 | 결과 |
| --- | --- |
| (확인 질문에 답을 적어 보냄) | 맞은 부분과 빠진 부분을 짚어 준다 |
| "더 쉽게" | 비유를 써서 다시 설명 |
| "더 깊게" | 프레임워크 내부 동작, 트랜잭션·스레드 관점까지 |
| "그건 알아" | 그 주제는 다시 길게 설명하지 않는다 |

## 팁
- 설명에 나온 코드 위치를 직접 열어 보면서 읽으면 효과가 크다.
- 정리하고 싶은 내용은 하루를 마칠 때 `/learn-note`로 학습 노트에 남긴다.
