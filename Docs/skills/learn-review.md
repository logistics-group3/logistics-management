# learn-review — 힌트부터 주는 학습용 코드 리뷰

> 분류: 학습 · 절차 원본: [`.claude/skills/learn-review/SKILL.md`](../../.claude/skills/learn-review/SKILL.md)

## 목적
일반적인 리뷰 요청은 AI가 바로 고쳐 버려서 스스로 고치며 배울 기회가 사라진다. 이 skill은 프로젝트 규칙(`CLAUDE.md`) 기준으로 문제를 짚되 **힌트부터 단계적으로** 준다. 요청하기 전에는 파일을 수정하지 않는다.

## 이럴 때 쓴다
- 직접 짠 코드를 커밋하기 전에
- `impl-service`로 만든 코드를 내가 고친 뒤 다시 점검할 때

## 호출
```
/learn-review                          ← 커밋 전 변경분 전체
/learn-review hub-service/src/main/java/com/sparta/logistics/hub/application
```

## 결과 구성
| 구역 | 내용 |
| --- | --- |
| 반드시 고칠 것 | 규칙 위반·버그. 위치 + **질문형 힌트** + 관련 규칙 |
| 고려해 볼 것 | 설계·가독성 개선 |
| 잘한 점 | 1~3개, 왜 좋은지 |

예시
```
## 반드시 고칠 것
1. HubStockRepository.java:21 — 힌트: "이 조회가 논리 삭제된 행도 가져오지 않을까?" (루트 CLAUDE.md §3-6)
```

## 힌트 단계
요청할 때만 다음 단계로 넘어간다.

| 단계 | 이렇게 말하면 | AI가 하는 일 |
| --- | --- | --- |
| 1. 힌트 (기본) | - | 질문으로 문제 지점만 가리킴 |
| 2. 방향 | "더 힌트", "모르겠어" | 무엇을 어떻게 바꾸면 되는지 말로 설명 |
| 3. 정답 | "정답", "코드로 보여줘" | 수정 코드 예시 |
| 4. 적용 | "네가 고쳐줘" | 파일을 직접 수정 |

## 다시 보기
고친 뒤 다시 `/learn-review`를 요청하면 이전 항목별로 **해결 / 미해결 / 새로 생긴 문제**를 표시한다.

## 팁
- 힌트 단계에서 최대한 스스로 고쳐 보고, 막힐 때만 단계를 올린다.
- 고치다가 알게 된 것은 `/learn-note`로 남기고, 오래 막혔던 문제는 트러블슈팅으로 기록한다.
