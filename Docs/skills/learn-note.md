# learn-note — 하루 학습 정리

> 분류: 학습 · 절차 원본: [`.claude/skills/learn-note/SKILL.md`](../../.claude/skills/learn-note/SKILL.md) · **직접 호출만 가능** (AI가 알아서 실행하지 않음)

## 목적
배운 것을 그날 정리하지 않으면 발표 직전에 몰아서 쓰게 되고 사람마다 형식도 제각각이 된다. 이 skill은 오늘 커밋과 대화를 바탕으로 학습 노트를 쓰고, 해결한 문제는 트러블슈팅에 기록한다.

## 이럴 때 쓴다
- 하루 작업을 마칠 때 (또는 큰 작업 하나를 끝냈을 때)

## 호출
```
/learn-note           ← git user.name으로 이름을 정함
/learn-note 권민혁
```

## 하는 일
1. **자료 모으기**: 오늘 내 커밋(`git log --since=midnight`), 이 대화에서 다룬 질문·설명·구현, 오늘 쓴 구현 노트
2. **학습 노트**: `Docs/team/학습-노트/{이름}.md` 맨 아래에 날짜 섹션 추가
   ```markdown
   ## 2026-10-15
   ### 오늘 한 일
   ### 배운 것
   - **{개념}**: 한두 줄 설명 — 우리 코드 위치
   ### 헷갈렸던 것 / 아직 모르는 것
   ### 다음에 할 일
   ```
3. **트러블슈팅**: 오늘 막혔다가 해결한 문제를 `Docs/07-트러블슈팅.md`에 `TS-{다음 번호}`로 추가. 원인을 확인하지 못했으면 "원인: 미확인"으로 쓴다.
4. **확인**: 작성한 내용을 보여 주고 고칠 부분을 묻는다.

## 주의
- 실제로 다룬 내용만 쓴다. 다루지 않은 개념을 채워 넣지 않으므로, 정리하고 싶은 내용이 대화에 없으면 직접 알려 준다.
- 구현 노트에 이미 있는 내용은 중복해서 쓰지 않고 링크만 건다.
- "헷갈렸던 것" 항목은 다음 날 `/learn-explain`으로 물어볼 목록으로 쓰면 좋다.
